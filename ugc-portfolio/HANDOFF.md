# סיכום העברה: אתר תיק עבודות UGC

המסמך הזה מסכם את כל מה שנבנה עד עכשיו, למי שממשיך את העבודה בלי גישה לשיחה המקורית (למשל Claude Code במחשב). כתוב כאן מה המטרה, מה נבנה, איך זה עובד, מה נבדק ומה עוד פתוח.

## המטרה
המשתמש (עמנואל) ראה אתר תיק עבודות של יוצרת תוכן UGC, שנבנה ב־Canva ופורסם ב־`my.canva.site`, ורצה אתר כזה למישהי שהוא מכיר.

דרישות שעלו בשיחה, לפי הסדר:
1. אתר באותו סגנון: רקע בהיר, כותרות סריף באנגלית, סרטונים בתוך מסגרות של טלפון, About me ופרטי קשר.
2. עיצוב "יותר יפה" ← עיצוב בסגנון מגזין אופנה.
3. צבע ורוד בהיר, פודרה.
4. שמי שמנהלת את האתר, בלי שום ידע טכני, תוכל לערוך אותו לבד: טקסטים, תמונות, סרטונים ומחירים. הפתרון: פאנל ניהול.

**חשוב:** האתר המקורי שימש רק השראה. אסור להעתיק ממנו טקסטים, שם, טלפון, מייל או תמונות. כל הפרטים באתר הם placeholders שמחכים לפרטים האמיתיים שלה.

## מבנה הקבצים
```

ugc-portfolio/
  index.html                  # כל העיצוב (CSS בתוך הקובץ) + סקריפט שממלא את העמוד מ־content/*.json
  content/profile.json        # שם, משפט פתיחה, תמונות, About, עיר/גיל/שפות/זמן מסירה, אינסטגרם/מייל/טלפון

```

## איך האתר עובד
- **אין build.** `index.html` הוא קובץ סטטי. בטעינה הוא עושה `fetch` לארבעת קובצי ה־JSON (עם `cache: 'no-cache'`) וממלא את העמוד.
- **הצגה:** עד שהתוכן נטען, `.site[data-state="loading"]` שקוף, ואז העמוד מופיע ב־fade-in.
- **שדות פשוטים:** טקסט נכנס דרך `data-bind="<key>"` מ־`profile.json`. השם נכנס דרך `data-name="stack|inline|plain"`, כשהשם השני מוצג באיטליק ורוד.
- **קישורים:** `data-link="instagram|email|phone|whatsapp"` ו־`data-show`. השדה `instagram` מנוקה אוטומטית (מסיר `@` וקישור מלא). קישור הוואטסאפ ו־`tel:` נבנים מהטלפון: `050-123-4567` ← `972501234567`.
- **רשימות:** סרטונים, סוגי תוכן, מותגים, שלבים, חבילות ותחומים נבנים ב־JS עם הפונקציה `el()`. תוכן משתמש נכנס תמיד דרך `textContent`, אף פעם לא דרך `innerHTML`.
- **אזורים ריקים:** רשימה ריקה מסתירה את האזור שלה עם `hidden`.
- **סרטונים:**
  - כשיש קובץ (`works[].video`), הוא מוצג כ־`<video muted loop playsinline>`. הוא מתנגן כשהוא בתצוגה (IntersectionObserver), ונגיעה מפעילה את הקול.
  - כשאין קובץ, מוצג רקע לדוגמה (`.scene-*`) עם כפתור play וכתובית לדוגמה (`hook`).
  - לסרטון אמיתי אין כפתור play ואין כתובית לדוגמה.
- **שם חבילה:** המילה האחרונה מוצגת באיטליק. למשל "The Trio" ← *Trio*.
- **עריכה מקומית:** פתיחה ישירה של הקובץ (`file://`) לא טוענת את ה־JSON. צריך שרת: `cd ugc-portfolio && python3 -m http.server`.

## העיצוב

  3. פס תחומים נע.

- **כללי עיצוב:**
  - האתר כתוב בעברית (`dir="rtl"`). קטעים באנגלית מקבלים `class="en"` (direction: ltr).

- **ניסוח:** הטקסטים בעברית ניטרליים מגדרית בגוף ראשון. לא ידוע אם בעלת האתר תרצה לשון זכר או נקבה, אז אין טקסטים כמו "יוצרת" או "מצלמת". כשהפרטים האמיתיים יגיעו, אפשר להתאים.

## פאנל הניהול (Decap CMS)
- **התחברות:** `backend: github` דרך ספק ה־OAuth המובנה של Netlify. העורכת צריכה חשבון GitHub והרשאת Collaborator בריפו.
- **למה לא התחברות עם מייל:** Netlify Identity ו־Git Gateway הוצאו משימוש באופן רשמי בפברואר 2025 (נתמכים רק בתיקוני אבטחה), אז הם לא נבחרו.
- **ממשק:** `locale: he`. הטפסים והתוויות בעברית. `editor.preview: false`, כלומר טופס נקי בלי חלון תצוגה מקדימה.
- **ארבעה חלקים:** פרטים אישיים, סרטונים, חבילות, ותחומים/סוגי תוכן/מותגים/שלבים. כל אחד הוא קובץ JSON.
- **מדיה:** `media_folder: ugc-portfolio/uploads`, `public_folder: uploads`. הנתיב יחסי, אז הוא עובד גם בשורש האתר וגם בבדיקה מקומית.
- **גרסה:** `decap-cms@3.16.3`, מקובעת. (3.17.x יצאה ממש לפני כן, ונמנענו מגרסה חדשה מדי.)
- **שמירה:** הפאנל שומר ל־`branch: main`. לכן המיזוג ל־`main` הוא תנאי לכך שהפאנל יעבוד.

## מה נבדק
- האתר נטען מה־JSON ונראה זהה לעיצוב הקודם, בדסקטופ ובנייד.
- סימולציה של תוכן ערוך:
  - סרטון MP4 אמיתי מתנגן אוטומטית, וכפתור ה־play והכתובית לדוגמה מוסתרים.
  - תמונה ראשית מוצגת.
  - שם חדש מופיע בכל המקומות ובכותרת הדפדפן.
  - קישור אינסטגרם מלא מנוקה ל־`@handle`.
  - טלפון ← `wa.me/972…` ו־`tel:+972…`.
  - רשימת מותגים ריקה מסתירה את האזור.
  - כש־`show_badge: false`, התג מוסתר.
- פאנל הניהול נבדק מקומית עם `local_backend: true` ו־`npx decap-server`:
  - מסך הכניסה בעברית ("התחברות עם GitHub").
  - ארבעת החלקים נטענים עם התוכן האמיתי.
  - שינוי שם ← **פרסום** ← **פרסום מיידי** נשמר נכון בקובץ, וכל שאר השדות נשמרו.
- **לא נבדק:** התחברות אמיתית עם GitHub דרך Netlify, והעלאת קבצים לריפו האמיתי. אפשר לבדוק את זה רק אחרי ההקמה.

## מה נשאר לעשות
1. **למזג** את `ccr-55672943-obnelx` ל־`main`, דרך PR או merge.
2. **להקים ב־Netlify:** Import from GitHub ← הריפו ← ענף `main`. ההגדרות כבר ב־`netlify.toml`.
3. **OAuth:**
   - ב־GitHub: Developer settings ← OAuth App. Homepage = כתובת האתר. Callback = `https://api.netlify.com/auth/done`.
   - ב־Netlify: Access & security ← OAuth ← Install provider ← GitHub, עם ה־Client ID וה־Secret.
4. **גישה:** היא פותחת חשבון GitHub, ומוסיפים אותה כ־Collaborator.
5. **תוכן אמיתי:** שם, שם משתמש, מייל, טלפון, שתי תמונות, סרטונים (MP4 אנכי, עד 20MB) ומחירים. אפשר להזין דרך הפאנל, או ישירות לקובצי ה־JSON ולתיקייה `uploads/`.
6. **אופציונלי, ריפו נפרד:** להעביר את האתר לריפו משלו, כדי שהעורכת לא תקבל גישה לכל `Agentai`. אחרי המעבר מעדכנים ב־`admin/config.yml` את `repo`, את נתיבי `file:` ואת `media_folder`, ומזיזים את `netlify.toml` לשורש הריפו החדש.
7. **אופציונלי, שיפורים:**
   - תמונת שיתוף (`og:image`) ו־favicon.
   - דומיין משלה.
   - התאמת לשון זכר או נקבה לטקסטים.

## בדיקה מקומית של הפאנל (בלי GitHub)
1. מוסיפים זמנית `local_backend: true` בראש `admin/config.yml`. **לא לעשות commit לשינוי הזה.**
2. בטרמינל אחד, משורש הריפו: `npx decap-server`. השרת רץ על פורט 8081.
3. בטרמינל שני: `cd ugc-portfolio && python3 -m http.server 8000`.
4. פותחים `http://localhost:8000/admin/`. כל שמירה כותבת ישירות לקבצים המקומיים.
